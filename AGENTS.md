## Workflow: beginner-phased-build

Build projects bottom-up in small versions, easiest first, for learning.

- Never start with architecture, frameworks, or the full design.
- Before writing anything, break the project into versions (v0, v1, v2...), each runnable and testable on its own.
- v0 is the dumbest thing that works: hardcoded values, one file, no abstractions.
- Each version adds exactly ONE new concept or difficulty.
- After each version: explain what was added and why, then stop and wait for me to run it and say "next".
- Only introduce abstractions when the previous version's pain justifies them.
- Ask me to predict the next step before showing it.
